# Макет новой CRM — план

Два условия, которые нельзя нарушить:

1. **Визуал новый.** Не копия вашей CRM, не Odoo, не шаблон. Свой язык.
2. **Ничего не теряется.** Каждая кнопка, поле, фильтр, право и состояние из текущей системы имеют место в макете. Не «примерно», а построчно — см. `PARITY.md`.

---

## 1. Концепция: «Терминал диспетчера»

Спокойная бумажная подложка, чернильная типографика, чёрные кнопки, один сигнальный оранжевый. Плотно по информации, свободно по воздуху. Всё читается за две секунды: где застой, где деньги, что делать дальше.

**Палитра (светлая):** бумага `#F5F3EF`, поверхность `#FFFFFF`, чернила `#111315`, линия `#E6E2DA`, **сигнал** `#FF5A1F`, деньги `#0F9D6E`, внимание `#C77A00`, опасность `#D93A3A`.
**Тёмная («ночная смена»):** `#0E1013` / `#161A1F` / `#262B31` / текст `#F2F3F4`, сигнал `#FF6A33`, деньги `#35D39A`.

**Шрифты:** Inter Tight (заголовки, цифры) · Inter (интерфейс) · JetBrains Mono (ИНН, номера заявок, суммы).

**Пять фирменных деталей:** цветной корешок карточки = этап · крупные KPI-цифры 44–56 px · моноширинные реквизиты · липкая командная строка с `⌘K` · индикатор «дней без движения».

**Экраны:** Обзор · Канбан лидов · Лиды списком · Карточка лида · Заявки · Карточка заявки · Клиенты · (плюс витрина `/kit` и, по желанию, календарь погрузок).

**Входа и авторизации в макете нет:** приложение открывается сразу на «Обзоре». Это осознанное решение — на макете смотреть дизайн, а не логиниться. В вашем проекте вход остаётся как есть, мы его просто не перерисовываем.

## 2. Как макет «ляжет» на ваш проект

Главный риск: красивый макет, который невозможно внедрить без переписывания всего. Снимаю его семью правилами.

### 2.1 Маршруты — один в один

| Ваш маршрут | Что в макете |
|---|---|
| `/login` | не рисуем: в проекте остаётся как есть |
| `/` | Обзор (бывший лаунчер + сводка) |
| `/crm` | Канбан лидов |
| `/crm?view=list` | Лиды списком |
| `/crm/leads/:id` | Карточка лида |
| `/customers` | Клиенты |
| `/shipments` | Заявки |
| `/shipments/:id` | Карточка заявки |
| `/accounting` | Бухгалтерия (заглушка) |
| `/admin/users` · `/admin/accountants` · `/admin/security` | Админка |

Никаких выдуманных экранов вместо существующих. Новое (например, календарь) — только добавлением, не заменой.

### 2.2 Компоненты повторяют реальные данные

- В макет переношу **ваши типы** `Lead`, `Shipment`, `Stage`, `Tag`, `User` из `frontend/src/shared/types` — только чтение, как контракт. Имена полей не переименовываю: `logist_contact`, `customer_price`, `carrier_tax`, `is_archived`.
- Мок-данные имеют **ту же форму, что ответы API**, а не «красивые» выдуманные объекты.
- Компоненты принимают те же пропсы. При переносе меняется одна строка: `lead={mockLead}` → `lead={lead}` из `useLeads()`. Хуки, мутации, dnd-логика остаются вашими.

### 2.3 Поведение, которое обязано сохраниться

| Что | Почему важно |
|---|---|
| URL-параметры `?search`, `?status`, `?employee`, `?view`, `?board` | ссылки пересылаются коллегам, это уже привычка |
| Дебаунс поиска 300 мс | иначе шторм запросов |
| Счётчик «1–50 из 340», догрузка | люди ориентируются в объёме |
| Автосохранение + индикатор, конфликт версий и кнопка «Загрузить актуальную карточку» | двое могут править одну карточку |
| Диалог «сохранить и выйти» | защита от потери данных |
| Проигранный лид — только чтение + восстановление | защита истории |
| Права: менеджер / админ, чужая доска, фильтр по сотруднику | иначе утечка данных |
| Приватность чужих активных лидов (усечённая плитка) | то же |
| Тёмная тема, вложения, превью файлов, тосты, скелетоны | уже есть и работает |
| Клавиатурное управление канбаном и объявления для скринридера | доступность уже сделана — не ломаем |
| Липкие шапки таблиц, горизонтальная прокрутка | большие списки |

### 2.4 Не выкидываем, а перегруппировываем

Правило: **редкое — не удаляется, а уезжает туда, где не мешает.**

- Паспорт водителя, подписант перевозчика, реквизиты клиента → секция «Дополнительно» в карточке заявки (свёрнута, но на месте).
- Причина проигрыша, история, вложения → вкладки карточки лида.
- Бэкапы и попытки входа → разделы «Безопасности».
- Массовое выделение строк → строка «Выбрано: N» с «Снять выделение», как сейчас.

### 2.5 Токены с обратной совместимостью

В макете — свои имена `--ui-*`. При переносе сначала добавляются `--ui-*`, а старые `--odoo-*` становятся алиасами на них. Тогда можно красить экран за экраном, не ломая остальные 200+ классов за один коммит.

### 2.6 Порядок внедрения

1. **Токены + шелл** — старые экраны выглядят почти как раньше, но в новой оболочке.
2. **Лиды** — канбан, список, карточка.
3. **Заявки** — список, карточка.
4. **Клиенты, админка, вход, обзор.**

Каждый шаг — отдельный PR, зелёные `npm run build`, vitest и Playwright, откат одним `git revert`.

### 2.7 Приёмка каждого экрана

Экран считается готовым, только когда в `PARITY.md` **все** его пункты отмечены «есть в макете», и вы прошли по списку глазами. Не «на глаз красиво», а «ничего не пропало».

## 3. Что делаю в песочнице

| Шаг | Результат |
|---|---|
| 1 | Каркас, токены, шрифты, оболочка, витрина `/kit` |
| 2 | Вход + Обзор |
| 3 | Канбан и список лидов |
| 4 | Карточка лида |
| 5 | Заявки: список и карточка |
| 6 | Клиенты, админка, бухгалтерия |
| 7 | Полировка: пустые состояния, загрузка, ошибки, контраст, адаптив |

Макет живой: переключение экранов, темы, плотности, фильтры, вкладки, поиск по мок-данным. Без сохранения, прав и API — это витрина дизайна.

---

## 4. Чего не будет

- Экрана входа и любой авторизации: макет открывается сразу внутри системы.
- Изменений в `Roses1s/crm` — пока вы не скажете «переносим».
- Новых API, миграций, бизнес-логики.
- Реальных клиентов и сумм: все данные вымышленные.
- Удалённых функций «потому что не влезло». Не влезло — значит уедет в свёрнутую секцию или вкладку.
