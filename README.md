# CRM Детроид — макет интерфейса

Макет нового интерфейса для CRM Детроид (транспортная компания). Это **не копия**
рабочей системы: вёрстка и оформление собраны с нуля с ориентиром на её функции.
Готовность отдельных функций отмечена в PARITY.md. Бэкенда нет — данные живут в браузере.

- Дизайн-план и принятые решения: [`PLAN.md`](PLAN.md)
- Матрица паритета «ничего не теряем»: [`PARITY.md`](PARITY.md)
- Паспорт проекта для следующего агента: [`docs/HANDOVER.md`](docs/HANDOVER.md)
- Текущий статус и журнал решений: [`docs/STATUS.md`](docs/STATUS.md)
- План переноса визуала в рабочую CRM: [`docs/PORTING.md`](docs/PORTING.md)
- Готовый промт для передачи: [`docs/MASTER_PROMPT.md`](docs/MASTER_PROMPT.md)

## Что это

- Светлая лавандовая тема и тёмная, три акцента, две плотности. В тёмной теме
  и выпадающие списки в цветах темы, без белых пунктов.
- Роль **менеджера** по умолчанию: своя доска, свои задачи и заявки, лиды коллег — усечённо.
- Роль **администратора** включается в настройках — появляется раздел «Администрирование»
  (внутри — панель управления), доски и заявки сотрудников, удаление лидов и заявок.
- Воронка с перетаскиванием карточек, звёздами приоритета, тегами, сворачиванием
  этапов и собственным редактором этапов.
- Заявки (список и полная карточка) и клиенты плитками — по образцу рабочей CRM.
- Адаптив до телефона: панель выезжает по кнопке, воронка идёт вертикальными секциями.
- Входа и авторизации нет: приложение открывается сразу внутри системы.

## Быстрый старт

Нужен Node.js LTS с [nodejs.org](https://nodejs.org) (MSI, `winget` не требуется).

```bash
npm install
npm run dev
```

Открыть `http://localhost:5173`. Проверка production-сборки:

```bash
npm run build
npm run preview
```

## Воронка: перетаскивание и этапы

**Карточки на доске:** название (с огоньком у горячих), контакт, теги, звёзды
приоритета, маржа по связанным заявкам, срок и аватар ответственного. Карточка
открывается кликом в любом месте; меню «⋯» на ней нет. Клик по звезде сразу меняет
приоритет (0–3, повторный клик по той же звезде снимает) и не открывает лид. Маржа складывает `сумму клиента − сумму перевозчика`
только у заявок с тем же `leadId`; у лида без заявок показано 0 ₽. Тот же
показатель используется в шапках этапов и списке лидов. Направление, материал и
тоннаж скрыты только на карточках — сами данные сохранены и видны в режиме
списка. Всплывающая подсказка о перетаскивании убрана.

**Над доской:** KPI, чипы «Все / Горячие / Просроченные», сумма маржи доски и
переключатель «канбан / список». Поиск — в верхней строке: название, ИНН, контакт,
телефон лидов этой доски.
Проигранные лиды на доске и в списке не показываются.

**Свёрнутые этапы:** кнопка в шапке колонки сворачивает этап в узкую полосу с
названием и счётчиком; клик по полосе разворачивает. На свёрнутый этап можно
бросить карточку. Набор свёрнутых этапов запоминается отдельно для каждой доски.

**Доска сотрудника (администратор):** выбор «Доска» над колонками или адрес
`/crm?board=N`. Сверху плашка «Доска сотрудника: …» с кнопкой «Вернуться к своей».

**«Маржа заявок» в KPI** — сумма фактической маржи всех заявок, связанных со
своими лидами. Это не выручка, не ожидаемая сумма и не сумма оплат. Фильтры
«Горячие» и «Просроченные» этот KPI не меняют. В исходном демо-наборе у 10 своих
лидов есть 5 связанных заявок на 213 000 ₽ маржи. У нового лида нет денежного
поля: пока к нему не добавлена заявка, его маржа равна 0 ₽.

**Новый лид:** в форме обязательны пять полей — Компания, ИНН, Контакт логиста,
Телефон логиста и E-mail. Кнопка «+» в шапке этапа открывает ту же форму и после
сохранения помещает лид в выбранный этап; она больше не создаёт пустую карточку.

**Перетаскивание** (`@dnd-kit/core` + `@dnd-kit/sortable`):

- карточку можно перенести на любой этап и поставить в нужное место внутри этапа;
- линия вставки показывает точку, куда встанет карточка, пустая колонка — слот «Отпустите здесь»;
- исходная карточка тускнеет, призрак поднимается над доской с наклоном и тенью;
- мышь — срабатывание после 6 px, палец — долгое нажатие 160 мс, клавиатура — Tab, Space, стрелки, Space, Esc;
- бросок мимо доски и на прежнее место ничего не меняет; после переноса клик не открывает карточку;
- порядок сохраняется и восстанавливается после перезагрузки.

**Этапы** — добавляются прямо в конце канбан-доски либо настраиваются в карточке
«Моя воронка» из настроек и через кнопку «⋮» в шапке колонки:

- «Добавить этап» в конце доски превращается в поле названия: Enter или клик мимо
  создают этап, Esc отменяет ввод; пустое название не сохраняется;
- новый этап получает следующий цвет из существующей палитры и подсказку по
  умолчанию, после чего их можно изменить в настройках;
- можно переименовать этап, задать подсказку, выбрать цвет из восьми, переставить
  стрелками или удалить;
- удаление этапа переносит его лиды на соседний этап; последний этап удалить нельзя;
- этапы принадлежат менеджеру: правки не затрагивают доски коллег.

## Карточка лида: полоса этапов

Если этапов больше шести, полоса не растягивается: видно не больше шести
этапов, окно центрируется по текущему, а скрытые сворачиваются в кнопку «…»
со счётчиком (`… 3`). По нажатию открывается список скрытых этапов — текущий
выделен, выбор сразу переключает этап. Меню рисуется поверх страницы
(`position: fixed`), потому что сама полоса прокручивается по горизонтали;
закрывается по клику мимо, Esc, прокрутке и ресайзу.

Логика окна повторяет `FormStatusbar` рабочей CRM, оформление — наше.
Компонент: `src/ui/StageBar.jsx`, стили: `src/styles/stage-bar.css`. Та же полоса
показывает статусы в карточке заявки.

Слева от полосы стоит кнопка **«Создать заявку»** (у проигранного лида её нет).
У проигранного лида справа от полосы — «Восстановить» (свой лид) или «Взять себе»
(лид коллеги).

## Карточка лида: действия

- **«Действия»** в шапке: «Отметить проигрышем», «Передать коллеге», «Удалить лид»
  (только администратор). Отдельной кнопки «Проигрыш» в карточке нет.
- **Проигрыш** — причина обязательна (справочник рабочей CRM: «Перестал возить»,
  «Отказ СБ», «Отказался работать»). Лид уходит с доски, карточка становится только
  для чтения: сверху плашка «Лид проигран», на листе — лента «Проигрыш», причина —
  отдельной строкой в блоке «Клиент».
- **Передача** — в два шага (выбор коллеги → подтверждение); вместе с лидом уходят
  его заявки. То же открывается кликом по продавцу в блоке «Клиент».
- **Удаление** — «Удалить лид без возврата?» → «Удалить навсегда»; заявки лида
  стираются вместе с ним.
- **Листалка** в шапке: предыдущий и следующий лид той же доски в порядке этапов, «N из M».
- Лид коллеги менеджер видит усечённо: название, ИНН и продавец.

## Карточка лида: поля клиента

В блоке «Клиент» строки: Компания, ИНН, Контакт, Телефон, E-mail, Приоритет,
Теги, Продавец, Оператор ЭДО, Бухгалтер; у проигранного лида добавляется
«Причина проигрыша». Приоритет — звёзды 0–3, как в рабочей CRM: клик ставит,
повторный клик по той же звезде снимает. Он сохраняется вместе с остальными
правками и сразу видно на доске и в списке. Теги выбираются из общего списка
или создаются на ходу; удалить тег из справочника может только администратор.
Поле «Должность» в форме и подписях карточек не показывается; под названием на
доске стоит только контактное лицо.

«Оператор ЭДО» — обычный `<select>`: Не указан · Контур.Диадок (СКБ Контур) ·
СБИС / Saby (Тензор) · Калуга Астрал (Астрал.ЭДО, 1С-ЭДО) · Такском ·
СберКорус. Справочник лежит в `src/mock/data.js` (`EDO_OPERATORS`), значение
пишется в поле `edo` лида и сохраняется вместе с остальными правками.

## Карточка лида: быстрая заявка

Кнопка **«Создать заявку»** стоит перед полосой этапов и в пустом состоянии
вкладки «Заявки». Она открывает быстрый диалог по образцу основной CRM; заявка
сразу получает связь с открытым лидом и после создания открывается её карточка.

Обязательны город и дата погрузки, город и дата выгрузки, а также перевозчик.
ИНН и контакт перевозчика необязательны. В быстром диалоге на каждое плечо —
один город; в карточке заявки можно добавить ещё. Адрес, груз и машина
получают пустые значения; цену клиенту и цену перевозчику можно указать прямо в
карточке заявки, после чего маржа пересчитывается на всех связанных экранах.
Новая заявка имеет статус «Новая», получает следующий номер `ЗВ-2026-…`,
сохраняется в `crm.shipments.<id>.v1` и сразу видна в карточке лида, общем
списке, меню и связанных показателях. Пока цены не указаны, она не прибавляет
маржу.

## Карточка лида: письмо клиенту

Кнопка «Письмо» открывает в новой вкладке Яндекс Почту с уже подставленным
получателем: `https://mail.yandex.ru/compose?mailto=mailto%3A<адрес>`. Тема и
тело не заполняются — поля остаются пустыми.

Адрес берётся **только сохранённый**: адрес, набранный в поле E-mail, но ещё
не сохранённый (автосохранение срабатывает через 3 секунды), в письмо не
попадёт — иначе письмо ушло бы на адрес, которого в карточке нет.

Если почты нет, адрес не похож на адрес или браузер заблокировал вкладку —
внизу справа появляется уведомление, а поле E-mail подсвечивается и получает
фокус. «Позвонить» пока декоративная.

Проверено прогоном: пустая почта → нет вкладки + уведомление; несохранённый
адрес → письмо не открывается; сохранённый → открывается нужный адрес;
заблокированная вкладка → уведомление.

## Карточка лида: правка полей

Название/компания, ИНН, контакт, телефон, e-mail, приоритет, оператор ЭДО и
бухгалтер редактируются прямо в карточке — как в рабочей CRM, без отдельного
режима «изменить»:

- правки копятся в черновике и **сохраняются сами через 3 секунды** — как в
  рабочей CRM; можно и вручную: Enter в поле, кнопка «Сохранить»;
- в шапке видно состояние: «Изменено» → «Сохранение…» → «Сохранено»;
  рядом кнопки «Сохранить» / «Отменить», Esc возвращает последнее сохранение;
- уход со страницы с несохранёнными правками дописывает их, а не теряет;
- «Отменить» возвращает последнее сохранение, перезагрузка страницы тоже;
- ИНН принимает только цифры, при совпадении с другим лидом показывается
  предупреждение — сохранять оно не мешает;
- сохранение пишет в `localStorage` (`crm.leads.<id>.v1`) через `updateLead`
  из `src/app/store.jsx`, поэтому новое название сразу видно на доске,
  в крошках карточки и на экране «Клиенты».

## Карточка лида: лента (чаттер)

Справа от листа карточки — лента событий и заметок, как в рабочей CRM. Та же
лента стоит в карточке заявки (свой демо-набор: создание из лида, смены статуса,
заметка логиста):

- шапка: режим «Лог примечания», поиск по ленте, вложения со счётчиком;
- редактор: аватар, растущее поле, скрепка, кнопка «Лог», чипы выбранных файлов;
- лента начинается на уровне полосы этапов: этапы стоят первым блоком левой
  колонки и закреплены при прокрутке формы, поэтому лента занимает всю высоту
  рабочей области;
- лента сгруппирована по дням: «Сегодня», «Вчера», «6 ноября 2026 г.»;
- свежие записи — сверху: и дни, и заметки внутри дня идут от новых к старым,
  после отправки лента подводится к началу;
- запись: автор, относительное время, текст; смена этапа показывается строкой
  «• Новый → Перезвоните (Этап)»; свои заметки можно править и удалять;
- вложения видны под записью: картинки превью, остальное — чипом с размером;
- данные лежат в `src/mock/chatter.js` и по форме совпадают с `TimelineEntry`
  рабочей CRM. События смены этапа здесь демонстрационные; журнал фактических
  правок и серверные операции с заметками ещё нужно подключить при переносе.

Новые заметки, их правки и локальные вложения живут только до ухода с экрана
или перезагрузки; на сервер и в localStorage они не записываются. Созданные
задачи и отметки их выполнения также пока хранятся только в состоянии экрана.

Размеры — как в рабочей CRM, но чуть шире: колонка **37,5 % рабочей области** (у них 34,3 %), во всю высоту
окна (`100vh − 96 px`), прижата к правому краю, с левой линией и фоном страницы
вместо карточки; аватары 34 px, отступы 16 px, текст 13 px, кнопка «Лог» 30 px.
Прокрутка — как в рабочей CRM: на десктопе с окном от 700 px по высоте
страница записи не прокручивается целиком, шапка карточки и полоса этапов
остаются на месте, а форма слева и лента справа прокручиваются независимо,
каждая в своей колонке. На меньшей высоте окна раскладка откатывается к
обычной прокрутке страницы, чтобы лента не обрезалась. Внутри ленты
прокручивается только список записей — шапка и редактор всегда на виду.

На ≤1240 px раскладка обычная: лента встаёт под лист карточкой высотой 560 px,
на телефоне занимает 72 % высоты экрана. Своя прокрутка не тянет страницу.

## Заявки

**Список** (`/shipments`) — колонки как в рабочей CRM: Номер, Дата создания,
Продавец, Клиент, Перевозчик, Статус, Маржа, Всего. Поиск в верхней строке, чипы
статусов, кнопка «Показать ещё N из M». Строка «Итого» считается по всему текущему
отбору — это сверх рабочей CRM. Менеджер видит свои заявки, администратор — все и
может выбрать сотрудника (`?employee=N`, плашка «Заявки сотрудника»).

**Карточка** (`/shipments/:id`) — полная форма по образцу `ShipmentFormPage`:
блоки «Заявка», «Погрузка», «Выгрузка», «Перевозчик», «Груз», вкладки «Позиции
заказа» и «Прочая информация», лента справа. Статусы: Новая · Проверена и
подписана заявка · Машина загрузилась · Машина выгрузилась — меняются сразу.
Остальные правки копятся и сохраняются сами через 3 секунды, по Enter или кнопкой.

- маршрут собирается из городов погрузки и выгрузки (`Москва, Тверь → Казань`);
- маржа = сумма клиента − сумма перевозчика; налог в марже не участвует, а сумма
  без налога отличается от суммы только при НДС 22 % (делится на 1,22);
- «Копировать» создаёт новую заявку со статусом «Новая» из того, что сейчас на
  экране, включая несохранённые правки;
- «Удалить» — только администратор: «Удалить заявку безвозвратно?» → «Удалить навсегда».

Поля заявки названы как в API рабочей CRM (camelCase); справочники и приведение
старых сохранений — в `src/lib/shipment.js`.

## Клиенты

Плитки как `CustomerTile` рабочей CRM: монограмма, название, ИНН, этап или
проигрыш, продавец; можно переключиться на таблицу. Сегменты «Все / Мои /
Проигранные». Активные лиды коллег закрыты замком (администратору открыты все),
проигранные может открыть и забрать себе любой сотрудник.

## Панель управления

Раздел «Администрирование» (`/admin`, только администратор) с меню слева, как в
рабочей CRM: «Пользователи», «Бухгалтеры», «Безопасность»; раздел живёт в адресе
(`?section=`). Сверх рабочей CRM: сводка KPI сверху, переключатели «Счета / Банк»
у бухгалтеров, двухфакторный вход и «одна сессия». Данные — в рамках открытой
страницы.

## Перед показом

1. `npm run build` проходит без ошибок.
2. Воронка: перетаскивание мышью, пальцем и с клавиатуры; линия вставки на месте.
3. Пустая колонка показывает слот, а не пустоту.
4. Этапы: создание, переименование, цвет, порядок, удаление с переносом лидов.
5. Тёмная тема: панель, таблицы, карточка лида, аналитика, админка.
6. Телефон: меню выезжает, воронка вертикальная, модалки снизу.
7. Перезагрузка страницы сохраняет этапы, лиды, порядок, теги и заявки.
8. Звёзды на доске меняют приоритет и не открывают лид; клик по карточке открывает лид.
9. Лид: «Действия» → проигрыш с причиной → «Восстановить»; передача; удаление (админ).
10. Заявки: список, поиск, «Итого»; карточка — автосохранение, «Копировать», «Удалить» (админ).
11. Тёмная тема: выпадающие списки без белого фона.

## Что осталось для переноса в рабочую CRM

Вёрстка готова, поведение подключается к вашему API:

- глобальный поиск `⌘K` и состояние поиска в адресе страницы;
- диалог «Есть несохранённые изменения» (берётся из рабочей CRM как есть);
- ошибки API с кнопкой «Повторить», загрузка списков с сервера;
- **Задачи** требуют новой сущности и API: тип, заголовок, лид, срок, ответственный, статус;
- **Аналитика** — эндпойнта отчётов; остальное считается из существующих лидов и заявок.
