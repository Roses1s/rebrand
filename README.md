# ТрансЛайн CRM

HTML-прототип CRM для логистики. Главная страница — канбан-воронка лидов.

## Страницы
1. **Лиды** (`index.html`) — канбан-воронка.
2. **Заявки** (`requests.html`) — реестр перевозок: статусы, ставки, маржа, карточка заявки.

## Возможности

### Лиды
- Канбан с этапами: **Новый → Перезвонить → Вышел на ЛПР → Потенциальный → Уехали → Ждем заявку**
- Перетаскивание карточек между этапами (drag & drop)
- Светлая и тёмная тема (переключатель в шапке, выбор запоминается)
- Поиск по компании, контакту, маршруту и менеджеру + фильтр по менеджеру
- KPI-панель: количество лидов, сумма воронки, средний чек, конверсия
- Карточка лида в боковой панели со сменой этапа
- Создание нового лида через модальное окно

### Заявки
- Реестр из 16 заявок: №, клиент, маршрут, груз, дата погрузки, ставки, маржа, статус, менеджер
- Статусы: **Новая → В работе → Машина назначена → В пути → Выгружено / Отменена**
- Табы по статусам со счётчиками, поиск, фильтр по менеджеру
- KPI: активные заявки, сумма, маржа в работе, «сейчас в пути»
- Карточка заявки: финансы, груз, перевозчик и водитель, смена статуса, история рейса
- Создание новой заявки через модальное окно

### Общее
- Переход между страницами через боковое меню; остальные разделы — заглушки «в разработке»

## Вариант 1. VS Code + Live Server (рекомендуется)

> Подробная пошаговая инструкция с нуля (установка VS Code, скачивание проекта,
> расширение, обновления, разбор проблем) — в файле **[VSCODE-SETUP.md](VSCODE-SETUP.md)**.


1. Установите [VS Code](https://code.visualstudio.com/).
2. Откройте папку проекта: **File → Open Folder…** → выберите папку, где лежит `index.html`.
   Важно открыть именно папку, а не отдельный файл.
3. Установите расширение: `Ctrl + Shift + X` → в поиске **Live Server** (автор *Ritwick Dey*) → **Install**.
   VS Code сам предложит его установить — проект уже рекомендует расширение в `.vscode/extensions.json`.
4. Запустите одним из способов:
   - кнопка **Go Live** в правом нижнем углу окна;
   - правый клик по `index.html` в панели Explorer → **Open with Live Server**.
5. Откроется **http://127.0.0.1:5500** — страница автоматически перезагружается при сохранении файлов (`Ctrl + S`).

Остановить сервер: нажать **Port: 5500** в строке состояния.

Порт и автосохранение уже настроены в `.vscode/settings.json`:
```json
{
  "liveServer.settings.port": 5500,
  "liveServer.settings.donotShowInfoMsg": true,
  "files.autoSave": "afterDelay",
  "files.autoSaveDelay": 800
}
```

Если порт 5500 занят — поменяйте `liveServer.settings.port` в настройках (или ответьте «Yes» на предложение VS Code взять другой порт).

## Остальные способы запуска

### Вариант 2. Без установки чего-либо
Откройте **`crm-standalone.html`** двойным щелчком — это страница «Лиды» целиком в одном файле
(стили и скрипты внутри). Ссылка «Заявки» в меню ведёт на `requests-standalone.html`.
Можно открывать и обычные `index.html` / `requests.html`, но тогда рядом должна лежать папка `assets/`.

### Вариант 3. Настоящий localhost без установок (Windows)
Двойной щелчок по **`Запустить на Windows.bat`** → `http://localhost:8000`.
Сервер работает на встроенном Windows PowerShell, права администратора не нужны.
Остановка — `Ctrl + C`. Если порт занят, скрипт сам возьмёт 8080 / 3000 / 5500.

### Вариант 4. Через Node.js (Windows / macOS / Linux)
```powershell
node serve.mjs          # http://localhost:3000
node serve.mjs 8080     # другой порт
npm start               # то же самое через npm
```

### Вариант 5. Через Python
```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

### Что-то не работает
| Симптом | Решение |
|---|---|
| Нет кнопки **Go Live** | Не установлено расширение Live Server или открыт отдельный файл вместо папки |
| `Порт 5500 занят` | Укажите другой порт в `liveServer.settings.port` или закройте предыдущий сервер |
| Страница не обновляется | Проверьте, что VS Code не в режиме «без сохранения» — нажмите `Ctrl + S` |
| Белая страница | Откройте `crm-standalone.html` — он не зависит от папки `assets/` |
| Не видно изменений в браузере | `Ctrl + F5` (жёсткая перезагрузка) |

## Как получать обновления проекта

Все мои изменения уходят в ветку `arena/53b90abe-rebrand` репозитория
`https://github.com/Roses1s/rebrand`.

### Если проект склонирован через Git (удобнее всего)
```powershell
git pull origin arena/53b90abe-rebrand
```
В VS Code то же самое: панель **Source Control** (`Ctrl + Shift + G`) → меню `⋯` → **Pull**.
Дальше Live Server сам перезагрузит страницу в браузере.

Если Git не установлен: `winget install Git.Git`, затем перезапустить VS Code.
Первичное клонирование (делается один раз):
```powershell
git clone -b arena/53b90abe-rebrand https://github.com/Roses1s/rebrand.git
```

### Если проект скачан ZIP-архивом
Скачайте архив заново и распакуйте **поверх** папки с заменой файлов
(или удалите старую папку и распакуйте новую), затем `Ctrl + F5` в браузере:
**https://github.com/Roses1s/rebrand/archive/refs/heads/arena/53b90abe-rebrand.zip**

### Точечно, если менялся один файл
Откройте файл на GitHub → кнопка **Raw** → `Ctrl + S` в папку проекта.
Обычно меняются: `index.html`, `assets/styles.css`, `assets/app.js`, `README.md`.
Файл `crm-standalone.html` пересобирается автоматически (`node build.mjs`) — в репозитории он всегда актуальный.

### Как обновляется сайт на локальном сервере (bat / node / python)

Наш собственный сервер ничего не «собирает» — он читает файлы с диска в момент запроса.
Поэтому после `git pull` (или распаковки нового ZIP) достаточно обновить страницу в браузере:

1. `git pull origin arena/53b90abe-rebrand` (или распаковать архив поверх папки);
2. `F5` в браузере (при сомнениях — `Ctrl + F5`);
3. сервер перезапускать **не нужно**, он продолжает отдавать файлы с тем же адресом.

Кэширование отключено в обоих серверах (`Cache-Control: no-cache`), так что браузер всегда
запрашивает свежие версии. Автоматической перезагрузки страницы, как в Live Server, здесь нет —
наш сервер не следит за файлами; если это важно, используйте Live Server или скажите —
добавлю авто-обновление по WebSocket/SSE.

Перезапуск сервера нужен только если менялись сами файлы `serve.mjs` / `serve.ps1`
или если вы вручную правили `crm-standalone.html` (его собирает `node build.mjs`).

### Как работает автообновление Live Server
Live Server вставляет в отдаваемую страницу WebSocket-скрипт. Когда вы (или я, после `git pull`)
сохраняете файл внутри открытой папки, расширение отправляет сигнал — браузер перезагружает страницу.
Это работает только по адресу `http://127.0.0.1:5500` (не `file://`) и только если файл сохранён на диск (`Ctrl + S`).
Если браузер не обновился — нажмите `Ctrl + F5`.

> Данные лидов пока хранятся в памяти страницы (`assets/app.js`), поэтому любая перезагрузка
> возвращает исходные 20 карточек. Если нужно, чтобы перемещения и новые лиды сохранялись —
> скажите, добавлю сохранение в `localStorage` (одна правка в `app.js`).

## Структура
```
index.html                  — Лиды (канбан-воронка)
requests.html               — Заявки (реестр перевозок)
assets/styles.css           — стили, темы, адаптив
assets/ui.js                — общие утилиты: темы, тосты, сайдбар, форматирование
assets/app.js               — данные лидов и логика воронки
assets/requests.js          — данные заявок и логика реестра
VSCODE-SETUP.md             — подробная инструкция по настройке в VS Code
GIT-PULL.md                 — как обновлять проект через git pull в VS Code
crm-standalone.html         — Лиды «всё в одном файле»
requests-standalone.html    — Заявки «всё в одном файле»
build.mjs                   — сборка автономных файлов из html + assets
.vscode/settings.json       — настройки Live Server (порт 5500, автосохранение)
.vscode/extensions.json     — рекомендация расширения Live Server
serve.mjs                   — локальный сервер на Node.js (без зависимостей)
serve.ps1                   — локальный сервер на Windows PowerShell
Запустить на Windows.bat    — двойной клик: поднимает сервер и открывает браузер
```

## Разработка
Правьте `index.html`, `requests.html`, `assets/styles.css`, `assets/app.js`, `assets/requests.js` —
Live Server перезагрузит страницу сам. После правок пересоберите автономные версии:

```bash
node build.mjs
```
