# Перенос визуала в рабочую CRM

Живой документ: как вёрстка этого макета переедет в `Roses1s/crm`.
Заведён 16.11.2026, пересверен и дополнен заданиями 17.11.2026.
Источник сверки CRM — ветка `arena/3d32f7ee-crm`, коммит `2f4e93a`;
это не указание менять текущую ветку агента. Код CRM здесь только читаем.

## Кто что делает

- **Этот репозиторий** (`Roses1s/rebrand`) — только макет. Здесь доделывается
  внешний вид всего, что есть в рабочей CRM, и готовятся задания на перенос.
- **Рабочая CRM** (`Roses1s/crm`) — там работает **другой агент**. В её код
  отсюда ничего не пишем. Владелец передаёт тому агенту задания из раздела 6
  этого документа по одному.
- Переносится **именно визуал**: разметка, стили, расположение, состояния.
  Логика, API, права, проверки, тесты и данные рабочей CRM остаются её.

## 1. Решения владельца (16.11.2026)

| Вопрос | Решение |
|---|---|
| Порядок работ | Сначала доделать макет, потом переносить |
| Как включать | Новый вид **рядом со старым**, по переключателю; старый работает, пока владелец не скажет «переключаем» |
| Задачи и Аналитика | В макете остаются; в рабочую CRM — **позже, полноценно**, отдельным проектом с сервером. До этого в новом виде их нет |
| Поля без сервера: оператор ЭДО, срок на карточке, порядок карточек внутри этапа, подсказка этапа | В макете **остаются**; в рабочую CRM — позже, когда сервер научится их хранить |
| Приоритет | **Звёзды 0–3**, как в рабочей CRM: клик по звезде сохраняет, повторный клик по той же снимает |
| Вход | Рисуется в новом стиле — **позже**: вход и авторизацию пока не трогаем |
| Лаунчер | Не трогаем: решается **позже**, вместе со входом, отдельным решением владельца |
| Прототип `/crm2` в рабочей CRM | Заменяется новым видом и затем удаляется |
| Меню «⋯» на карточке доски (16.11) | **Не рисуем**: карточка открывается кликом по любому месту, звёзды меняют приоритет без перехода |
| Кнопка «Проигрыш» у полосы этапов (16.11) | **Не рисуем**: проигрыш — только пункт «Действия → Отметить проигрышем»; логика и диалог CRM без изменений |
| «Создать заявку» в карточке лида (16.11) | Стоит **перед** полосой этапов, слева; у проигранного лида справа от этапов — «Восстановить» / «Взять себе» |
| Выпадающие списки в тёмной теме (16.11) | Пункты раскрытого списка — цвета темы (фон `--surface`, текст `--ink`), иначе Windows рисует их белыми |
| ИНН на карточке доски (16.11, после код-ревью) | **Не показываем**: на карточке только название; в CRM сейчас «Компания — ИНН» — в новом виде ИНН с карточки убрать, в списке и карточке лида он остаётся |
| Массовое «Удалить» в списке лидов (16.11) | **Нет**, как в CRM: у выделения только «Снять выделение». Из макета убрано |
| Мелкие аватары (16.11) | Размер `sm` действует (22 px в клиентах-таблице, аналитике, задачах); там, где размер задан местом — лента 34 px, «Продавец», плашка доски, выбор коллеги 24 px, ответственный на карточке 20 px, — без изменений |
| Аватары (16.11, по скриншоту основной CRM) | У всех людей **один вид**: квадрат со скруглением 4 px (`rounded-[4px]`, как сейчас в CRM), градиент `#7563EA → #9E83F7` под 135°, белые инициалы жирностью 800, без обводки. Цвета по сотрудникам убраны. В CRM форму оставить, заменить только заливку `bg-odoo-avatar` / `bg-odoo-primary` на этот градиент. Размеры места сохраняются. Образец — `.avatar` в `src/styles/ui.css` |
| Список лидов: группы и догрузка (16.11, после контрольной проверки) | Как в CRM: список всегда разбит на группы по этапу («● Этап (N)»), группы идут в порядке строк после сортировки; под списком «Показать ещё N из M» порциями по 80, внизу колонки доски — «Показать ещё N из M» порциями по 20. Макет приведён к этому |
| Закрытие окна кликом по фону (16.11) | **Нет**, как в CRM: окно закрывается кнопкой или Esc. Макет приведён к этому |

## 2. Почему нельзя «скопировать папку»

| | Макет | Рабочая CRM |
|---|---|---|
| Язык | JavaScript (JSX) | TypeScript, строгие типы |
| Стили | собственные CSS-файлы, токены в `tokens.css` | Tailwind v4, токены `--odoo-*` в `index.css` |
| Данные | `localStorage`, `src/app/store.jsx` | API через react-query (`shared/api/hooks`) |
| Проверки | `npm run build`, SSR-смоук | ESLint, Prettier, `tsc -b`, 64 файла unit/integration-тестов с порогом покрытия, 2 e2e-файла, сборка |
| Сборка | Vite 8 | Vite 6 |

Поэтому каждый компонент переписывается: разметка и классы берутся из
макета, а данные и обработчики — из существующего кода рабочей CRM.

### 2.1. Риски переноса и как их обойти (пересверено 17.11.2026)

Сверено с веткой `arena/3d32f7ee-crm` (коммит `2f4e93a`) только чтением — в
рабочую CRM ничего не писали. Каждый пункт учтён в заданиях раздела 6.

| # | Риск | Что в рабочей CRM | Как обойти |
|---|---|---|---|
| R1 | **Шрифты не загрузятся.** Макет берёт Inter и JetBrains Mono с Google Fonts | Nginx отдаёт политику безопасности `font-src 'self' data:`, `style-src 'self' 'unsafe-inline'` (`deploy/nginx/snippets/security-headers.conf`); сейчас шрифт системный | Шрифты — файлами из npm: `@fontsource-variable/inter` и `@fontsource-variable/jetbrains-mono` (5.3.0, лицензия OFL-1.1), импорт в `main.tsx`; они отдаются со своего домена. Политику безопасности **не ослаблять**. Inter Tight не нужен — в макете он не применялся и убран 16.11 |
| R2 | **Тёмная тема включается иначе** | Класс `.dark` на `<html>`: `public/theme.js` (до отрисовки) и `shared/lib/theme.ts`, ключ `crm-theme`; `@custom-variant dark` | Значения тёмной темы макета (`html[data-theme="dark"]` в `tokens.css`) писать под `.dark`. Атрибут `data-theme` и свой ключ хранения не вводить |
| R3 | **Новый вид рядом со старым** (решение 1) | Токены `--odoo-*` (тройки RGB) в `:root` / `.dark` + `@theme inline` в `src/index.css`; ими крашен весь старый вид | Значения `--odoo-*` **не менять**. Для нового вида — отдельный набор токенов (например, `--nv-*`) со значениями из `tokens.css` макета для светлой и тёмной темы, утилиты через `@theme inline` (`--color-nv-*`); применять только в компонентах нового вида |
| R4 | **Скругления и тени** | Грабли v4 из `AGENTS.md`: `shadow-sm`→`shadow-xs`, `rounded`→`rounded-[4px]`; общий `--radius: 0.375rem` | Общий `--radius` не трогать. Радиусы и тени нового вида — произвольными значениями (`rounded-[14px]`, `rounded-full`) или своими токенами |
| R5 | **Ширины экранов** | Tailwind по умолчанию: 640 / 768 / 1024 / 1280 px | В макете переломы 680 / 900 / 1240 px. Брать произвольные `max-[680px]:`, `max-[900px]:`, `max-[1240px]:`; стандартные точки Tailwind не переопределять |
| R6 | **Линтер доступности** | `jsx-a11y` (recommended) + ошибки `click-events-have-key-events`, `no-static-element-interactions` | Разметка макета проходит эти правила, кроме Enter / Esc, повешенных на контейнер формы (`LeadPage.jsx`, `ShipmentPage.jsx`). Этот приём не переносить: поведение клавиш в формах — как в CRM |
| R7 | **Окна** | `shared/ui/modal.tsx`: фокус заперт в окне и возвращается назад; клик по фону **намеренно не закрывает** окно | Оформление окна — из макета, поведение — из CRM (запирание фокуса и возврат). По фону окно не закрывается ни там, ни в макете (решение 16.11) |
| R8 | **Покрытие тестами** | 64 файла тестов, порог покрытия: строки 60 %, ветки 58 % (`vite.config.ts`) | Новые компоненты без тестов могут уронить порог, и проверка покрытия в CI упадёт. В каждом задании — тесты на новый вид (можно повторить существующие тесты экрана для нового вида) |
| R9 | **Иконки** | `lucide-react` 0.474, в макете — 1.x | Проверено: все 42 иконки макета есть в 0.474. Версию в CRM не поднимать |
| R10 | **Встроенные стили** | Tailwind-классы; dnd-kit и цвета также используют динамический `style` | Статическое оформление макета переводить на классы/токены. Динамические transform, координаты меню и цвета серверных этапов оставить по механике CRM, не заменять ради формального отказа от `style` |

Без рисков: React 19, React Router 7, dnd-kit (те же версии), TanStack
Query и Zod (данные остаются серверными), Vite 6 против 8 (сборка остаётся
своя), `color-mix()` и `:has()` (их поддерживают все браузеры, которые
нужны Tailwind v4).
