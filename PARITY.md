# Матрица паритета: что есть сейчас → где будет в макете

Смысл документа: **ни один элемент текущей CRM не должен исчезнуть**. Здесь перечислено всё, что реально есть в коде (`arena/3d32f7ee-crm`), и указано, где это окажется в новом дизайне.

Обозначения в колонке «Как»:

- **видно** — на экране сразу, без клика;
- **свёрнуто** — секция «Дополнительно», раскрывается;
- **вкладка** — внутри экрана на отдельной вкладке;
- **меню** — в выпадающем меню «…» или в меню профиля;
- **диалог** — модальное окно;
- **состояние** — показывается по условию (пусто, ошибка, загрузка).

Статусы: `план` → `в работе` → `готово`. Ставлю по мере вёрстки, чтобы вы могли проверять не «на глаз», а по списку.

**Сверено 14.11.2026 с кодом `635ec83`** для воронки и карточки лида. «Готово»
ниже означает готовность в границах макета, не подключение к рабочему API.
Локальное автосохранение лида, переключение роли и заметки уже реализованы;
конфликты версий, серверные права, загрузка на сервер и пагинация не подключены.
Если выполнена только часть исходной функции, стоит «в работе»; отдельный
видимый элемент сам по себе не означает полной готовности пункта.

Отдельный статус **`вне макета`** — элемент существует в рабочей CRM и остаётся там без изменений, но в макете не рисуется (например, вход и авторизация).

маржа заявок этого лида и срок. Маржа складывается только по `leadId`; у лида
без заявок показано 0 ₽. Направление, материал и тоннаж скрыты только на
карточке; данные и режим списка сохранены. Всплывающая подсказка о
перетаскивании убрана, клавиатурное управление и атрибуты доступности сохранены.

или оплаты.

## J. Что добавляется сверх существующего (не вместо)

Кандидаты исходного плана, а не список уже реализованных или заново согласованных
функций. Стартовый экран макета по PLAN — воронка, не отдельный «Обзор».

| № | Что | На каких данных |
|---|---|---|
| J1 | Экран «Обзор»: KPI, воронка, «требует внимания» | существующие списки лидов и заявок |
| J2 | Глобальный поиск `⌘K` по лидам, заявкам, клиентам | существующий поиск API |
| J3 | Сводки в колонках канбана: количество, «висит N дней» | `updated_at` лида |
| J4 | Индикатор «дней без движения» на карточке | `updated_at` |
| J5 | Быстрые действия на карточке (позвонить, передать, проиграть) | существующие мутации |
| J6 | Вид «доска» для заявок по 4 статусам | `shipment.status` |
| J7 | Сохранённые фильтры (в браузере пользователя) | query-параметры + localStorage |
| J8 | Переключатель плотности интерфейса | только вёрстка |
| J9 | Календарь погрузок/выгрузок | даты заявок |
| J10 | Итоговая строка по выборке заявок (кол-во, маржа) | суммы из списка |

**Перенос в рабочую CRM — по отдельному решению и API:** точные отчёты за период,
серверные массовые действия, напоминания, экспорт в Excel, печать заявки, уведомления.
Локальное массовое удаление лидов в макете уже есть и не означает готовность
соответствующих серверных операций.
